## 内容组织规则

### 分类：文章属于哪个领域

每篇文章原则上使用一个主分类。新的技术内容优先归入上述六个方向；已有编程语言、工具和博客搭建内容保留合适的归属，不为了凑导航强行分类。

现有内容建议整理为：

| 文章 | 建议主分类 | 处理说明 |
| --- | --- | --- |
| Python 笔记 | 编程语言 | 保留，逐步拆分具体主题 |
| C 语言字符串函数 | 编程语言 | 保留，补充适用范围与示例 |
| NumPy 笔记 | 数据与计算 | 可从数学或机器学习导航页关联 |
| Markdown 笔记 | 工具与效率 | 保留 |
| Hugo 搭建过程 | 博客建设 | 已更新为当前部署方式 |
| 旧 Hexo 教程 | 博客建设 | 保留，标注历史适用环境 |
| PyTorch 空白笔记 | 待整理 | 不凭空补写正文，决定补充或退出首页 |
| Rich Content、Test 分类 | 历史示例 | 不纳入六个方向的推荐，后续处理 |

分类标签已于 2026-11-13 完成第一轮整理。示例文章和空白 PyTorch 笔记暂不分类，保留原文和访问地址；后续再处理正文与展示状态。

### 标签：涉及什么技术或概念

每篇文章通常使用 2～5 个有效标签，短文不强求数量。统一大小写和名称，例如 `Python`、`PyTorch`、`Kubernetes`、`OpenTelemetry`；避免为同一概念建立多个写法。

标签可以是工具，也可以是具体概念，如 CNI、虚拟内存、梯度下降。不要把所有相关领域都加成分类，也不要为一篇文章罗列整套技术栈。

### 系列：读者按照什么顺序学习

系列负责组织有阅读顺序的一组文章，例如“Kubernetes 网络”。文章可以属于一个主分类，同时加入一个系列。

系列的字段、索引页和导航尚需实现。只在 Front Matter 添加 `series` 并不意味着 Stack 已自动提供所需的系列导航。

### 内容形式：这篇文章怎么写

优先准备四种模板：

- **原理解析**：问题、直觉、机制、例子、适用范围。
- **实验实践**：目标、环境版本、操作步骤、预期结果、实际验证。
- **排障记录**：现象、证据、定位过程、原因、修复、验证。
- **数学推导**：符号与前提、直觉、推导步骤、数值或代码验证。

文章与学习笔记都允许发布，但要让读者知道它是系统教程、局部记录，还是尚在探索的结论。

## 首页与导航设计

已确定：首页以六个知识方向为主要入口，最新文章作为补充，不再只依靠时间列表找文章。

### 首页主区域

- 六个方向入口：标题、范围说明、已发布相关文章数量。
- 桌面两列，手机单列，沿用 Stack 的视觉风格和明暗主题。
- 下方显示最近更新的 5 篇文章，优先按 `lastmod`，没有时按发布日期。
- 暂时没有内容的方向有真实可访问的介绍页，说明“计划更新”，不放空链接。

### 主题页与知识导航页

统一知识导航页汇总六个方向。各主题页逐步加入范围说明、系列入口和相关文章；有实际内容后再扩展阅读路线。

主题页允许关联其他分类中的文章，例如数学基础页面可以关联 NumPy 笔记，不必为此给文章堆叠分类。

### 侧栏

| 位置 | 计划内容 |
| --- | --- |
| 左侧固定导航 | 首页、知识导航、归档、关于；GitHub、RSS |
| 首页右侧 | 搜索、最近更新 |
| 文章右侧 | 文章目录 |
| 手机导航 | 保留可发现的搜索入口 |

分类和标签页面保留，通过知识导航和文章元信息访问。首页不再堆叠大标签云与重复的月份归档。

这部分目前是设计，尚未替换线上首页。实施时先完成基础导航，再根据真实文章数量调整展示。

## 可以使用哪些 skill

- **brainstorming**：讨论选题范围、信息结构和页面方案。
- **product-design:audit**：在能够访问浏览器和截图时检查导航与阅读体验。
- **skill-creator**：把稳定的分类词表、文章模板和发布流程制作成个人 skill。
- **verification-before-completion**：在完成修改、发布前运行实际检查，以检查结果记录完成状态。

skill 用于帮助执行工作，不能代替文章中的推导、实验和事实核验。个人博客 skill 尚未创建，先让真实写作积累出可复用的规则。

## 如何持续更新本篇

每次建设或规划调整都修改这篇源码：

1. 在对应段落更新决定，明确区分计划与已实现功能。
2. 只在实现并验证后勾选待办。
3. 更新 `lastmod`，保留首次发布日期和 `slug: blog-roadmap`。
4. 在下方追加简短记录，说明完成事项和下一步。
5. 与相关代码或配置一起提交，经过构建校验后发布。

不在文章里记录访问令牌、数据库密码或其他凭据。具体实现以仓库代码为准，规划与实现不一致时同步修订本篇。
