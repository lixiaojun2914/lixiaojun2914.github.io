## C 端抓包：清空 A 的邻居后从 A ping B

窗口先开（终端一）：

$ sudo ip netns exec nslab-c timeout 20 tcpdump -nn -e -i c0

终端二清邻居再 ping：

$ sudo ip -n nslab-a neigh flush dev a0
$ sudo ip netns exec nslab-a ping -n -c 2 10.77.1.2

终端一收到 19 帧，其中 ARP 只有一条：

09:00:43.919897 02:00:00:77:01:01 > 33:33:00:00:00:16, ethertype IPv6 (0x86dd), length 90: fe80::40ca:fdff:fec9:3e86 > ff02::16: HBH ICMP6, multicast listener report v2, 1 group record(s), length 28
09:00:43.919945 02:00:00:77:01:01 > 33:33:00:00:00:02, ethertype IPv6 (0x86dd), length 70: fe80::40ca:fdff:fec9:3e86 > ff02::2: ICMP6, router solicitation, length 16
09:00:43.919979 02:00:00:77:01:02 > 33:33:00:00:00:16, ethertype IPv6 (0x86dd), length 90: fe80::49e:63ff:feed:df6f > ff02::16: HBH ICMP6, multicast listener report v2, 1 group record(s), length 28
09:00:43.919979 02:00:00:77:01:02 > 33:33:00:00:00:02, ethertype IPv6 (0x86dd), length 70: fe80::49e:63ff:feed:df6f > ff02::2: ICMP6, router solicitation, length 16
（中间若干条同类 IPv6 帧与一条 IGMP 报告，略）
09:00:46.871131 02:00:00:77:01:01 > ff:ff:ff:ff:ff:ff, ethertype ARP (0x0806), length 42: Request who-has 10.77.1.2 tell 10.77.1.1, length 28

19 packets captured
19 packets received by filter
0 packets dropped by kernel

说明：19 帧里只有这一条 ARP 广播，没有 ARP 应答，也没有 ICMP 单播。A 发往 B 的 ARP 请求是广播，FDB 未知或广播都会泛洪到 pc，所以 C 看得见；B 的应答是单播，FDB 已知 B 在 pb，只从 pb 发出，C 看不到。其余 18 帧是刚建好接口的端点发出来的 IPv6 组播侦听报告、邻居请求、路由请求和一条 IGMP 报告，与实验无关。

$ sudo ip -n nslab-a neigh
10.77.1.2 dev a0 lladdr 02:00:00:77:01:02 REACHABLE
